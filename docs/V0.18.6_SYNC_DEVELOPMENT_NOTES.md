# Fakturiva v0.18.6 — zapis razvoja i provjera nakon spajanja

**GitHub stanje (14. 11. 2026.):** PR [#38](https://github.com/bren-wp/Fakturiva/pull/38) spojen je u `main` commitom `7de2d9addeae0745645327e706a0ac77b34e40e8`. Objavljeno je izdanje [`v0.18.6-preview.1`](https://github.com/bren-wp/Fakturiva/releases/tag/v0.18.6-preview.1), koje sadržava debug APK, debug-potpisani i nepotpisani AAB, Windows i web pakete. Nijedan od tih AAB-ova nije potvrđen kao vlasnički potpisan Google Play release paket. To **ne dokazuje** instalaciju na produkcijskom hostingu niti vizualnu 1:1 podudarnost. GitHub Actions za merge SHA prijavio je uspjeh za Android, screenshot, responsive, Windows, PHP i preview distribuciju; nije proveden neovisni produkcijski end-to-end test.

## Web, Android, Windows i poslužitelj

- `web/business.php` prima stvarno evidentiranu djelomičnu ili potpunu uplatu izdanog računa istim email/password korisničkim računom kao Android. Windows WebView2 koristi isti portal.
- `web/lib_payment_sync.php` provjerava identitet računa, status `ISSUED`, nepodmireni saldo iz već spremljenih uplata, datum i stvarni kanal. Iznosi se pretvaraju u cente bez floating-point zaokruživanja pri upisu; plaćeni račun dobiva status `PAID`.
- `web/lib_business_sync.php` novu uplatu zapisuje preko postojećeg transakcijskog `expected_revision` CAS-a kao kompletnu AES-256-GCM `FAK1` presliku. Nema dodatne nesinkronizirane web baze ni promjene SQLite sheme.
- Android `CloudMirror.pullNewer` odbija obnovu ako je lokalni profil prljav, u sukobu, pauziran ili ima nedovršen radni nacrt, uključujući provjeru neposredno prije zamjene SQLite baze.
- `quality/web-hosting/business-sync-smoke.php` pokriva djelomičnu/potpunu naplatu, preplatu, datume, kanale, CAS 409 i očuvanje identiteta i iznosa povijesnih dokumenata.
- Web obrazac prilagođen je malim ekranima i koristi dostupne HTML oznake, bez generiranih slika.

## Web CRUD računa i ponuda

- `web/documents.php` omogućuje otključavanje vlastitog poslovnog stanja, prikaz računa i ponuda, izradu, uređivanje i brisanje nacrta, te potvrdu i jedinstveno numeriranje dokumenata. Potvrđena ponuda može se označiti prihvaćenom ili pretvoriti u novi nacrt računa.
- `web/lib_documents_sync.php` replicira schema-8 format i matematička pravila Android `Store`/`Money`: količine su u tisućinkama, cijene i PDV u integer centima, a zakonski odabrana stopa prenosi se istim kodom. Nema promjene SQLite sheme.
- Potvrđeni dokumenti ne mogu se uređivati niti brisati web CRUD-om, a nevaljane veze, ID-jevi, brojači dokumenata ili pogrešni iznosi odbijaju se prije spremanja šifrirane revizije.
- HTTP 409 zbog paralelnih izmjena zaustavlja upis. Web može prikazati samo nespremljena korisnička polja u jednokratnom odgovoru radi ručne usporedbe, bez spremanja lozinke, automatskog mergea ili prepisivanja druge revizije.
- `.github/workflows/live-https-probe.yml` provodi samo javni GET `/api.php?action=health` s TLS provjerom; ne pokušava prijavu niti promjene produkcije. Status tog probnog poziva nije dokaz da je nova verzija instalirana ili da je potpun end-to-end login/sync uspio.

## Obvezne provjere za sljedeću izmjenu i produkcijski rollout

1. Na konačnom PR SHA mora proći kompletni Android build/lint, Python testovi, PHP `-l`, izolirani transakcijski smoke test, 20 stvarnih snimki Android zaslona, responsive QA te Windows build.
2. Izraditi kopiju postojećeg `web/storage/data`, `web/storage/secret.php` i Android exporta prije testiranja migracije ili prvog stvarnog upisa.
3. Na staging HTTPS serveru testirati web uplatu, Android `status/load`, automatski pull u čist profil, stariji lokalni offline zapis, račun iz druge valute, drugi korisnički račun i sukob revizija, bez pristupa produkcijskim korisničkim podatcima.
4. Usporediti svih 20 stvarnih Android PNG zaslona s izvornim referencama istog viewporta i gustoće. Postojeći RGB MAE prosjek 8,29/255 nije 0 %. Bez izvornih PNG referenci i usporedbe po pikselu ne tvrditi vizualnu 1:1 podudarnost.
5. Za sljedeći PR najprije proći sve relevantne CI provjere i pregled koda, pa tek onda odlučiti o spajanju. Novo izdanje mora imati APK, AAB, Windows/web pakete i SHA256SUMS te jasno označiti debug/unsigned artefakte. Produkcijski AAB mora se potpisati odgovarajućim vlasničkim ključem.

## Što još nije implementirano

- CRUD nacrta i potvrda postoje na webu; još nisu implementirani puni web PDF/ispis, storno već izdanih dokumenata sa svim pravnim provjerama i službene fiskalizacijske integracije.
- Bezgubitno entitetsko spajanje istodobnih offline izmjena na više uređaja; server koristi cijeli šifrirani snapshot i revizijski CAS. Kod sukoba korisnik mora ručno razriješiti podatke.
- Provjereni deployment na `https://fakturiva.eu/` i test stvarnih korisničkih računa iz produkcije.
- Dokaz 0 % vizualnog odstupanja svih 20 referentnih zaslona i svih rezolucija.

## Post-merge sigurnosni nalaz i regresija

- Codex pregled PR-a #38 upozorio je da `doc_add`, `doc_edit` i `quote_convert` mogu stvoriti presliku s više od 100.000 dokumenata ili stavki, koju Android `Store.restore` odbija.
- Naknadni fix sprječava objavu takvih preslika HTTP odgovorom `413`, uključujući zamjenu stavki nacrta na graničnoj vrijednosti i pretvaranje ponude u račun; dodan je sintetski test `quality/web-hosting/document-capacity-smoke.php` u PHP CI workflow.
- Ova korekcija ne mijenja postojeće korisničke račune, dokumente, sigurnosne kopije, SQLite shemu ni podatke na serveru. Njezino spajanje i novo izdanje zahtijevaju provjeru CI-a.
